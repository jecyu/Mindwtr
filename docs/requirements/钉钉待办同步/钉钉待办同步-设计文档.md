## 1. 背景与目标

用户（本仓库 owner）在钉钉里有大量待办，希望在 Mindwtr 里统一查看。当前 Mindwtr **没有**消费外部 MCP 服务的能力——`apps/mcp-server` 是反向的（把 Mindwtr 暴露给 AI 工具，`docs/ARCHITECTURE.md:16`）。

目标：桌面端设置页新增「钉钉待办」集成区块，点按钮手动拉取钉钉待办并写入 Mindwtr。

**不在本次范围**：定时自动同步、通用 MCP 接入框架、移动端、反向回写、子待办。

---

## 2. 范围对齐

| 项 | 定义 |
|---|---|
| **触发** | 设置页「立即同步」按钮，手动，无调度器 |
| **拉取范围** | `roleTypes: ['executor','creator']` × `todoStatus: ['false','true']` 共 4 个分页查询 |
| **落点** | 不建 project / area；出现在 Inbox 视图 |
| **状态映射** | **已完成的待办不导入**（实测 144 条已完成 vs 275 条未完成，Inbox 只放未完成的工作）；未完成 → `'inbox'`。已完成那一桶仍拉取，仅用于把已存在的任务标记完成 |
| **拉取范围** | `roleTypes: ['executor','creator']` × `todoStatus: ['false','true']` 共 4 个分页查询（`'true'` 桶不建任务，只喂 reconcile） |
| **完成态方向** | 单向：钉钉 → Mindwtr。**反向不生效** |
| **远端其它变更** | 标题 / 截止时间**不同步** |
| **钉钉侧消失** | Mindwtr 对应任务**不动** |
| **本地编辑过的任务** | 完成态**仍然同步**（不沿用 CSV provenance 守卫） |
| **子待办** | 忽略 |

### 3.2 ⚠️ `applyImport` 的 skip 语义（本方案的核心约束）

`packages/core/src/import-apply.ts:431-436`：
```ts
if (existingTaskIds.has(taskId)) {
    if (deletedTaskIds.has(taskId)) skippedDeletedTaskCount += 1;
    else skippedExistingTaskCount += 1;
    return;                    // ← 一个字段都不更新
}
```

**两个后果**：
1. 「钉钉完成 → Mindwtr 完成」不会自动发生 → **必须新增 reconcile**
2. 「标题/截止时间不同步」目前是这条 skip 的**副作用**，代码里**无任何字段级过滤**。reconcile 一旦写 `status`，该隐含假设即失效 → **reconcile 必须显式限定写入字段**

其他关键点：
- `import-apply.ts:191`：`const idFor = opts.idFor ?? (() => uuidv4());` —— **不传 `idFor` 会退化成随机 UUID，幂等彻底失效**
- `import-apply.ts:180`：已调 `ensureDeviceId(currentData.settings)` → 返回值 `data.settings.deviceId` 保证存在
- `import-apply.ts:437-438`：`projectId` 仅由 `projectSourceKey` 决定；`areaId` 仅由 `areaSourceKey` 决定 → **两者都不传即为 standalone（Inbox）**

- `TaskStatus` 枚举：`packages/core/src/types.ts:3` = `'inbox'|'next'|'waiting'|'someday'|'reference'|'done'|'archived'`

## 4. 目标规则与算法

### 4.1 映射规则

| 钉钉 | Mindwtr | 规则 |
|---|---|---|
| `taskId` | `sourceKey` | 直接使用 |
| `subject` | `title` | 剥离 `[图片]` 前缀 → 取**首个非空行**；完整原文 + 链接进 `description`。**清理后为空则回退保留 `[图片]` 原文** |
| `priority` 10/20/30/40 | `TaskPriority` | 映射；**字段缺失时用默认值** |
| `dueTime` | `dueDate` | **`null` 与 `0` 均视为无日期**；否则 epoch ms → ISO |
| `createdTime` | `createdAt` | epoch ms → ISO |
| `finalStatusStage === 2` | **不建任务**；仅参与 reconcile | 已完成的不导入 |
| 否则 | `status: 'inbox'` | 未完成 |
| ~~`detailUrl.pcUrl`~~ | ~~`description`~~ | **不写入**：钉钉小程序深链，浏览器打开是空白（依赖钉钉容器）。见需求对齐文档 |
| — | project / area | **不传** → standalone |

### 4.2 reconcile 算法

```
输入：applied.data.tasks（applyImport 之后）、远端 todo 映射（id → { done, doneTime }）
输出：打过补丁的 tasks + 计数

deviceId = applied.data.settings.deviceId      // applyImport 已 ensureDeviceId
updatedAt = new Date().toISOString()

for task in applied.data.tasks:
    todo = remoteById.get(task.id)
    if !todo: continue

    // ---- 跳过条件（缺一不可）----
    if task.deletedAt || task.purgedAt: continue        // 墓碑，尊重用户删除
    if task.cancelledAt:               continue         // 用户主动取消，改 done 会破坏取消语义
    if isTaskFinished(task):           continue         // 已 done/archived，跳过以避免 rev 抖动
    if !todo.done:                     continue         // 仅正向转换

    // ---- 写入：白名单字段，其余原样保留 ----
    result.push({
        ...task,                                        // ← 其余字段原样展开
        status: 'done',
        completedAt: todo.doneTime ?? updatedAt,        // 不可省略
        updatedAt,
        rev: nextRevision(task.rev),
        revBy: deviceId,
    })
```

**白名单是硬约束**：`status` / `completedAt` / `updatedAt` / `rev` / `revBy`。`title` / `dueDate` / `description` / `projectId` 等**绝不出现**在补丁里——这是 §3.2 隐含前提失效后的唯一防线。

### 4.3 手算验证（走一遍完整生命周期）

| 时刻 | 钉钉侧 | Mindwtr 侧（同步后） | 依据 |
|---|---|---|---|
| T1 首次同步 | `taskId=A`，未完成，due=1000 | 新建 task（id=`uuid5('mindwtr:dingtalk-import:v1:task:A')`），`status='inbox'`，`dueDate=1000`，`rev=1` | `import-apply.ts:437` 无 project → standalone |
| T2 再同步（无变化） | 同上 | **无变化**。`importedTaskCount=0`，`skippedExistingTaskCount=1` | `import-apply.ts:431-436` |
| T3 钉钉标记完成 | `finalStatusStage=2` | `status='done'`，`completedAt=` **同步时刻**（见 §5.6-8），`rev=2`，`revBy=deviceId` | §4.2 |
| T4 再同步（已 done） | 同上 | **无变化**，`rev` 仍为 2 | `isTaskFinished` 跳过 → 不抖动 |
| T5 用户在 Mindwtr 改标题 | 同上 | 标题保留用户版本；完成态**已同步过**故无动作 | 白名单不含 `title` |
| T6 用户在 Mindwtr 删除 | 同上 | **不复活** | `deletedAt` 跳过 + `applyImport` 墓碑守卫 |
| T7 钉钉侧删除 | 列表不再出现 A | **无变化** | 需求决策「不动」 |

## 5. 技术方案

### 5.1 选型一：是否扩 `ImportSourceId`

| 方案 | 代价 | 结论 |
|---|---|---|
| A. 加 `'dingtalk'` 进 `ImportSourceId` | 打断两个穷尽 Record：`apps/desktop/src/lib/data-transfer.ts:356`、`apps/mobile/lib/data-transfer.ts:237`。其字段是 `accept`/`extensions`/`title`（文件选择器元数据），对网络拉取毫无意义 → 被迫塞假条目。另需改 `import-runner.ts` 的 `:48`/`:49`/`:56-64`/`:99-107`/`:120+` | ❌ |
| **B. 直接调 `runDataTransferTransaction`** | 传 `operation: 'syncDingTalk'`。仍免费获得 recovery snapshot、陈旧守卫、写锁串行化 | ✅ **采用** |

**选 B 的理由**：A 的收益只是"类型上归入导入族谱"，代价是往文件导入器里注入永不会被调用的死配置，且要动移动端。B 拿到全部事务保证，且零污染。

### 5.2 选型二：是否沿用 CSV 的 provenance 守卫

| 方案 | 行为 | 结论 |
|---|---|---|
| A. 沿用 `rev===1 && createdAt===updatedAt` | 用户改过标题的任务，**完成态永远不再同步** | ❌ |
| **B. 不沿用，改用字段白名单** | 完成态始终同步；标题/截止靠白名单保护 | ✅ **采用** |

**选 B 的理由**：CSV 守卫保护的是**容器归属**——结构性变更，与用户在 Mindwtr 里的本地重组直接冲突，所以必须让位。完成态是**生命周期事实**，与标题/容器无冲突，可以安全地独立同步。两者性质不同，不能类比。

### 5.3 选型三：MCP 客户端实现

| 方案 | 代价 | 结论 |
|---|---|---|
| A. 用 `@modelcontextprotocol/sdk` | 它只是 `apps/mcp-server` 的 **devDependency**；依赖含 `express`/`hono`/`cors`/`ajv`/`cross-spawn`；`exports` 无 `browser` 条件；`client/index.js` 顶层 import ajv → Vite bundle 风险 | ❌ |
| **B. 手写最小 JSON-RPC 客户端** | ~80 行：`initialize` → `notifications/initialized` → `tools/call`，带 `Mcp-Session-Id` 与 SSE 分帧。零新依赖 | ✅ **采用** |

### 5.4 选型四：UI 范式

采用 `SettingsEmailCaptureSection` 的自包含范式（§3.8）→ **`SettingsView.tsx` 与 `SettingsView.test.tsx` 零改动**。

### 5.6 实现要点核对表

| # | 要点 | 依据 |
|---|---|---|
| 1 | `idFor` **必须传** | `import-apply.ts:191` 默认随机 UUID |
| 2 | 按 `taskId` **去重** | executor+creator 会重复返回同一条 |
| 3 | 显式拉 `todoStatus: 'false'` + `'true'` **两个桶** | 实测默认只返回未完成 |
| 4 | 两个桶**各自分页**到 `hasMore === false` | 实测两桶均 `hasMore: true` |
| 5 | `dueTime` 的 `null` **与** `0` 都当无日期 | 两种形态都实测到 |
| 6 | `priority` 缺失时用默认值 | 实测有缺失 |
| 7 | reconcile **白名单字段** | §3.2 隐含前提失效 |
| 8 | `completedAt` **显式赋值**，值为**同步时刻** | 列表接口 `get_user_todos` 不返回完成时间，只有 `get_todo_detail` 有 `finishTime`（逐条调用代价高）。显式赋值是为了避免被 `normalizeTaskLifecycleFields` 回填成别的值；已知偏差：完成时间是同步时刻而非钉钉勾选时刻，需求方 2026-09-25 确认接受 |
| 9 | reconcile 跳过 `deletedAt`/`purgedAt`/`cancelledAt`/`isTaskFinished` | 墓碑 + 取消语义 + 防抖动 |
| 10 | `revBy` 取 `applied.data.settings.deviceId` | `import-apply.ts:180` 已 ensureDeviceId |
| 11 | `updatedAt` 用 ISO-8601 且 `>= createdAt` | `task-status.ts` 的 `normalizeTaskForLoad` 会校验 |
| 12 | 注入 `getTauriHttpFetch()`，**不要**用 `globalThis.fetch` | `useAiSettings.ts:277` 是 CORS 反例 |
| 13 | 会话 `finally` 关闭 + 超时 | MCP streamable HTTP 会开 SSE |
| 14 | `desktopBoundaries` 需 **export** | 目前是 `data-transfer.ts:180` 模块私有 |
| 15 | 新增 core 模块需加进 `index.ts` barrel | `index-exports.test.ts` 规则 3 |
| 16 | 新设置 key 需进 `SETTINGS_SEARCH_MOBILE_EXCLUSIONS` | 否则 `apps/mobile/.../settings.search.test.ts:130-146` 硬失败 |
| 17 | 空值语义：URL 回显给渲染进程（照 `get_ai_key`），**输入框保存后清空**避免凭证留在屏幕上 | 曾考虑 `hasUrl` 不回显，但渲染进程必须拿到 URL 才能发请求；清空输入框即消除了误抹风险 |

## 8. 测试方案

### A. 纯逻辑层（主要防线，不需要网络）
`bun --cwd packages/core test dingtalk-import`

覆盖：幂等（连跑两次）、墓碑不复活、已取消不翻转、已 done 不 bump rev、`completedAt` 取钉钉时间、executor+creator 去重、`dueTime` 的 `null`/`0`、`priority` 缺失、纯 `[图片]` 兜底、已完成待办不导入、**reconcile 后 `title`/`dueDate` 未被改动**（防 §3.2 回归）。

### 实测校准（2026-09-24，真实网关，实现阶段发现）

这三个只有打真实网关才会暴露，已固化进实现与测试：

| # | 发现 | 影响 |
|---|---|---|
| 1 | **`pageSize` 上限 20**；21/25/30/50/100 一律返回 `{"result":{"todoCards":null}}` 且 `isError:false` | 用 50 会**永远静默导入 0 条**。已改用 20，并把「`todoCards` 不是数组」当错误抛出而非当空结果 |
| 2 | **鉴权失败 = HTTP 200 + JSON-RPC error body**（`[UNAUTHORIZED] Token验证失败`），非 401/403 | 只判状态码会漏掉过期。已改为解析 error message |
| 3 | 网关**间歇性返回空 result**（19 次连发偶发一次，同页单独重试正常） | 已加 3 次重试；鉴权错误不重试 |

另：`Accept: application/json, text/event-stream` 是**必需**头，缺失返回 HTTP 406；网关无状态，`initialize` 非必需。

### B. 传输层（不需要真实钉钉）
本地 HTTP server 模拟 streamable-HTTP（先例 `apps/mcp-server/src/http-server.test.ts:287`）：分页循环、SSE 分帧、超时、会话关闭、错误分类。注入普通 `fetch`。

### C. 事务落库
对 `syncDingTalkTodos` 注入假 fetch：新任务 `projectId === undefined`、reconcile 后 `rev` 恰好 +1、`revBy === settings.deviceId`、`saveData` 只调一次。

### D. 真实端到端
`bun run desktop:web` → 设置 → 集成 → 填真实地址 → 同步 → Inbox 出现任务且描述含链接 → 钉钉勾选完成 → 再同步 → 变 done 且 `completedAt` 是钉钉时间 → Mindwtr 删除 → 再同步 → **不复活** → 改错地址 → 报错可读且提示更新。

### E. 守卫全绿
`bun run typecheck && bun run lint:all && bun run test && bun run i18n:check`
最易漏：`apps/mobile` 的 `settings.search.test.ts`。
