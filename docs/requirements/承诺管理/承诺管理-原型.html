按 P 值排序 —— 承诺卡是一个排序维度，不是新的任务列表。任务评了承诺卡仍留在原位置。

✓ 承诺管理不占侧栏位置

它由两个正交部分组成：承诺卡（任务编辑器里的面板）+ 按 P 值排序（排序下拉框的一项）。 侧栏与 upstream 完全一致 —— 零新增导航项。

为什么选 P 排序时要折叠分区：Agenda 既有分区是 focus / schedule / reviewDue / next / upcoming（focus-sections.ts:268）。 若保留分区、只在段内按 P 排，跨分区就不可比 —— P 值高的可能排在 P 值低的下面，痛点「不知道保哪个」就没解决。

折叠后时间信息不丢：降级为行内徽章 —— 📅 今天 📅 逾期 ⏱ 未来 10-05。 判断复用 isTodayScheduleCandidate()（focus-sections.ts:53， 其注释自称是"今天"的唯一答案；注意 due <= endOfToday，逾期也滚动进今天）。 「今天」徽章总是显示，与承诺管理解耦 —— 可独立验证、独立回滚。

落点：focus-sections.ts（churn=7，315 行）。改动是守卫式新增 —— if (sortBy === 'commitment') 才进新分支。移动端 / widget / native host 不选这个排序时代码路径根本不进入，行为零变化。 相比改 AgendaView.tsx（churn=175），合并冲突风险低 25 倍。
